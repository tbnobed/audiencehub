Import performance fix. Found on the production server with py-spy: imports ran at 14–69 rows/s. Causes and required changes:

1. Worker concurrency uses threads in one process, so concurrent jobs share one core under the GIL, and every per-row database round trip waits up to the 5 ms switch interval to reacquire it. Replace thread concurrency with processes: WORKER_CONCURRENCY spawns that many worker processes (multiprocessing, spawn start method), each claiming one job at a time via SKIP LOCKED. Keep the scheduler loop in exactly one process. Also support running multiple worker containers (docker compose --scale worker=N); document it in DEPLOYMENT.md.
2. Per-row INSERTs in run_import (app/imports/service.py around line 618) must become set-based: COPY each 10k batch into an unlogged staging table, then one INSERT ... SELECT ... ON CONFLICT DO UPDATE per target table (source_records, gifts, events, enrichment_values, consents). No per-row round trips anywhere in the import path, including blocklist and suppression checks (one query per batch).
3. Email validation runs twice per row (imports/validation.py and identity/normalize.py) and email_validator's IDNA domain parsing dominates CPU. Normalize once per row in the import path and pass the result through. Add a fast path: ASCII addresses matching a strict regex skip email_validator and only lowercase/strip-tags; cache domain validation with functools.lru_cache(maxsize=100_000); call email_validator only for non-ASCII or unusual addresses. Keep all existing normalization tests passing and add tests proving fast-path and slow-path results are identical on a 10,000-address fuzz set.
4. Add a scale test to the benchmark command: python -m app.cli benchmark --imports generates a 1,000,000-row gift file and a 500,000-row contact file, imports both concurrently, and prints rows/s per import. Acceptance: at least 5,000 rows/s per import with two running concurrently on 4 vCPU, and 1M gift rows in under 5 minutes.
5. Fix the Docker WORKDIR so "docker compose exec api python -m app.cli ..." works without -w, and add a "kinship" console script.
Report py-spy-style evidence (or cProfile top 20) before and after for a 100k-row gift import.
